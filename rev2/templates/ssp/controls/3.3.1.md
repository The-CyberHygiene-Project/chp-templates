**Implementation:** auditd runs on every host from boot, with the CUI profile's rules. These record failed access, permission and ownership changes, deletions, privileged commands and logins. Records are flushed to disk as they are written. With the optional document server (from ISO 0.7.0), NextCloud's audit log (sign-ins, downloads, uploads, deletions, share attempts) is read by Wazuh on the server, and each new controlled document, checkout, approval, override and publication is one entry in the document ledger: hash-chained, append-only, written only by root on the server, with its head copied to the site stick at each export. The ledger records the account that Kanidm names for the request, never a typed name. These records and the alert text can carry CUI file names and folder paths; they stay on the appliance (monitor, Wazuh, daily review) and are not forwarded off it.

**Site responsibility:** Retain audit records for {{decision.audit_retention_days}} days, including copies kept off the host, so they remain available for investigation. Treat the document server's audit log, the Wazuh records and the document ledger as CUI, and keep them inside the boundary.
