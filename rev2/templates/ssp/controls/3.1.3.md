**Implementation:** firewalld is enabled on every host, with only the services each role needs opened. With the appliance's optional document server (from ISO 0.7.0, NextCloud on the server), CUI stays inside the CUI, FCI and Archive team folders: their share permission is off, public links to anything tagged CUI or FCI are refused, a file leaves CUI only for Archive, every attempt to share or move CUI out is refused and raises a high-priority alert at once, and NextCloud itself is refused any connection to the internet. Each night a local NextCloud account, `chp-canary` (outside Kanidm, disabled between runs), tries a public link and an internal share on a CUI test file and alerts if either is not refused. A member of `cui-users` can still download a CUI file and upload it elsewhere: the owner accepts this as an insider risk; every download and upload is recorded in the audit log (Wazuh), and the site rule in the guide forbids it. Because the FIPS database cannot compute MD5, NextCloud refuses to move, rename or delete a folder with files in it, or to move a file with old versions to another team folder; the server reports this as "DEGRADED: database MD5 unavailable", and an administrator makes such moves by the guide's procedure.

**Site responsibility:** Define where CUI may flow (systems, people, outside parties), enforce it at the site's network boundary, and record the approved flows. Adopt the guide's rule that CUI downloaded from the document server is never uploaded outside the CUI folders, train users on it, and review the download and upload records.
